redis vs pgvector

Semantic Search & Routing

Side-by-side vector search, hybrid semantic search, and semantic intent routing — Redis (RedisVL) vs Postgres (pgvector) — over a fictitious credit-card company's transactions, card products, and support FAQ. Same corpus, same embeddings, same questions.

Vector search

Exact (FLAT/KNN) and approximate (HNSW) nearest-neighbor search over 40,000 embedded transactions.

Semantic search

Natural-language search over card products and FAQ articles, combined with category/fee filters in one query.

Semantic caching

RedisVL's SemanticCache vs Postgres, which has no caching layer and recomputes every single call.

Semantic routing

RedisVL's built-in SemanticRouter vs a hand-rolled pgvector equivalent — routes straight into the matching search.

No real customer or transaction data of any kind. See Methodology.
